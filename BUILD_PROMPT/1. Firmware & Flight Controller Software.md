You are a senior embedded systems engineer specializing in micro-drone firmware.

Design and implement the complete flight controller firmware for Quicknitch — a 32g palm-sized
autonomous flying AI companion device.

Hardware platform:
- Primary SoC: ESP32-S3 (dual-core Xtensa LX7 @ 240MHz, 8MB PSRAM, 16MB flash)
- IMU: ICM-42688-P via SPI at 8MHz, 500Hz ODR for attitude, 1kHz for rate
- Barometer: BMP388 via I2C
- Optical flow: PMW3901 via SPI
- Motor drivers: 8x DRV8837 H-bridge, PWM via LEDC peripheral at 25kHz
- Proximity: 4x VL53L4CX via I2C with interrupt pins
- Camera: OV2640 via 8-bit parallel + VSYNC/HREF/PCLK

Implement the following in C using ESP-IDF v5.1:

1. RTOS TASK ARCHITECTURE
   - Define all FreeRTOS tasks with stack sizes, priorities, and core affinity
   - Task list: imu_task (Core 1, priority 20), flight_ctrl_task (Core 1, priority 19),
     motor_task (Core 1, priority 18), sensor_task (Core 0, priority 15),
     comms_task (Core 0, priority 14), camera_task (Core 0, priority 12),
     safety_task (Core 1, priority 25 — highest)
   - Define all inter-task communication queues and semaphores
   - Include watchdog timer setup per task

2. IMU DRIVER AND ATTITUDE ESTIMATION
   - Full ICM-42688-P SPI driver (register map, init sequence, FIFO read)
   - Madgwick AHRS filter implementation in fixed-point arithmetic
     (avoid FPU bottleneck during high-rate loop)
   - Gyro bias calibration on startup (500-sample average while stationary)
   - Output: quaternion + Euler angles at 500Hz to shared memory struct

3. CASCADED PID FLIGHT CONTROLLER
   - Outer loop at 100Hz: position/velocity controller (X, Y, Z axes)
   - Inner loop at 500Hz: attitude controller (roll, pitch, yaw rates)
   - Full anti-windup, derivative filter (Butterworth 2nd order, cutoff 50Hz)
   - Bumpless transfer on mode switch
   - Motor mixing matrix for coaxial + lateral rotor geometry:
     * 2 coaxial motors (top/bottom) for Z-thrust
     * 4 lateral tilt motors for X/Y/yaw
     * 2 auxiliary stabilization rotors
   - Output: 8-channel PWM commands (0–2000µs)

4. ALTITUDE HOLD
   - Fuse BMP388 barometer (5Hz, median-filtered) with IMU Z-axis acceleration
     via complementary filter
   - PID altitude controller feeding coaxial motor throttle
   - Implement aggressive landing detection (throttle < 15% AND altitude rate > -0.05 m/s
     for 500ms triggers landed state)

5. OPTICAL FLOW NAVIGATION
   - PMW3901 SPI driver with motion burst read at 100Hz
   - Convert pixel flow to velocity estimate using altitude and camera focal length
   - Fuse with IMU for XY velocity estimation
   - Position hold PID using velocity integral

6. OBSTACLE AVOIDANCE
   - VL53L4CX I2C driver, all 4 sensors on separate I2C buses (ESP32-S3 has 2
     hardware I2C, use 2 software I2C for remaining 2)
   - Read all 4 at 30Hz via interrupt-driven polling
   - Implement potential field repulsion: any sensor < 30cm generates a
     proportional velocity command opposing the obstacle direction
   - Emergency stop: any sensor < 12cm triggers immediate hover and alert

7. SAFETY SYSTEM
   - Hardware watchdog: if flight_ctrl_task misses deadline by >5ms, cut all motors
   - Freefall detection: |accel| < 0.3g for >150ms → motor cutoff, LED alert

     max throttle by 30%
   - Low battery: at 3.5V (per BQ25180 ADC), initiate auto-land sequence
   - Lost comms: if no command heartbeat for >3 seconds, return to last known
     home position and hover

8. STATE MACHINE
   Implement a hierarchical state machine with these states:
   - BOOTING → CALIBRATING → DOCKED → ARMED → HOVERING → FOLLOWING
     → ORBITING → RETURNING → LANDING → EMERGENCY
   Define all transition conditions and entry/exit actions for each state.

9. MOTOR CALIBRATION AND ESC
   Since motors are direct PWM (no ESC), implement:
   - Startup sequence: all motors spin at 5% for 500ms, then stop (clears stiction)
   - Per-motor trim values stored in NVS flash
   - Automated motor balance test on first boot: spin each motor individually,
     measure resulting IMU perturbation, compute and store compensation offsets

10. CODE QUALITY REQUIREMENTS
    - All code in C99
    - Full Doxygen comments on every function
    - Unit test stubs for PID controller, Madgwick filter, and motor mixing
    - No dynamic memory allocation after init phase (all static or stack)
    - Worst-case stack usage analysis comments per task
    - Include complete CMakeLists.txt for ESP-IDF project structure
